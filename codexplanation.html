60-Second Project Summary for Your Teacher

Use this concise overview when introducing what ResourceHub does and how it is architected:

ResourceHub is a full-stack academic resource library built with React, Supabase, and Node.js Serverless Functions.

It supports two roles: Facilitators (Teachers) and Students. When a user signs in via Supabase Auth, the application queries our PostgreSQL profiles table to determine their role.

Facilitators can upload PDF, PPT, and PPTX study materials up to 20 MB to Supabase Storage and connect their Google Drive via OAuth 2.0. Students can search, filter by subject or file type, sort by newest or most liked, bookmark resources, download files, and preview materials directly in the browser.

Because web browsers cannot natively render PowerPoint files, our backend endpoint (/api/google/preview.js) temporarily uploads PPT/PPTX files to Google Drive, exports them as PDFs on the fly, streams the PDF to the browser modal, and deletes the temporary file immediately inside a finally block.

Core System Workflows

How data flows between the React components, Supabase, and the Node.js serverless endpoints:

01 · Authentication

Session & Role Verification

AuthForm.js authenticates users with supabase.auth. App.js listens via onAuthStateChange, fetches the user's role from the profiles table, and conditionally renders facilitator tools.

02 · Storage

Facilitator Resource Upload

UploadForm.js validates file extensions (PDF, PPT, PPTX) and size (≤ 20 MB), then invokes addResource() in App.js to upload the binary to Supabase Storage and insert metadata into the resources table.

03 · OAuth 2.0

Google Drive Authorization

GoogleDriveConnect.js calls /api/google/auth.js, which sets an HMAC-signed CSRF cookie and redirects to Google. /api/google/callback.js verifies the signature and stores the refresh_token in google_drive_tokens.

04 · Preview Pipeline

In-Browser Document Rendering

In ResourceRow.js, PDFs are downloaded directly from Supabase Storage into a local Blob URL. PPT/PPTX files are routed through /api/google/preview.js for server-side PDF conversion before rendering inside an <iframe>.

Read-only inputs passed from a parent component down to a child component, similar to function arguments.

A React Hook that preserves local state across renders and triggers an automatic UI update whenever the setter function is called.

useEffect()

A React Hook used to synchronize components with external systems (such as fetching from Supabase or revoking Blob URLs in memory).

JavaScript syntax for handling asynchronous Promises cleanly without blocking the main browser thread during network requests.

A long-lived credential stored securely on the backend that allows the server to request fresh Google Drive access tokens when a teacher is offline.

Viva & Presentation Notes

Q: Why are there two separate useEffect hooks in App.js?

The first useEffect (lines 29–57) runs once when the app starts to check if a user is logged in and listen for login/logout events. The second useEffect (lines 59–189) depends on [session]—so whenever a user logs in or out, it automatically fetches that user's profile role and loads the resources from Supabase.

Q: What is the purpose of the 'let mounted = true' variable inside useEffect?

Network requests to Supabase are asynchronous (they take time). If a user closes the page or logs out while a request is still in flight, 'if (!mounted) return;' prevents React from trying to update state on an unmounted component, avoiding memory leaks and console warnings.

Q: How does addResource() handle database errors after a file is already uploaded to storage?

On lines 304–308, if inserting the metadata row into the 'resources' table fails after the file was uploaded to Supabase Storage, it runs 'await supabase.storage.from("resources").remove([filePath])' to clean up and delete the orphaned file!

Q: Why does line 79 use `crypto.timingSafeEqual()` instead of normal `===` to compare signatures?

Standard string comparison (`===`) stops at the very first mismatched character, taking slightly different amounts of nanoseconds depending on how many characters matched. Hackers can measure those tiny time differences ('timing attacks') to guess a signature! `crypto.timingSafeEqual()` always takes the exact same amount of time.

It performs an UPSERT (Update or Insert) in PostgreSQL! If this facilitator already connected Google Drive in the past (`on_conflict=user_id`), it updates their existing row with the new token instead of crashing with a duplicate key error.
